# 공원 산책 (프로그래머스 Lv.1)

## 문제 요약
- `park`: 문자열 리스트로 된 공원 지도
  - `"S"` 시작 지점, `"O"` 지나갈 수 있는 길, `"X"` 장애물
- `routes`: `"E 2"`처럼 **방향 + 칸 수**가 공백으로 붙은 명령 리스트
  - 방향: `N`(북), `S`(남), `W`(서), `E`(동)
- 명령대로 이동하되, 이동 중 **공원을 벗어나거나 장애물을 만나면 그 명령 전체를 무시**하고 다음 명령으로
- 최종 위치를 `[세로 좌표, 가로 좌표]`로 반환

> [!info] 유형
> [[캐릭터의 좌표]]의 확장판
> 같은 뼈대: **다음 위치 계산 → 검사 → 이동**
> 새 요소: 시작 위치 찾기, 문자열 명령 분리, 장애물, **여러 칸 이동 + 전부 통과해야 이동**

---

## 1차 분석 (내가 찾은 새 요소)
- park는 리스트 안의 값 하나하나를 읽어와야 함
- routes는 공백을 분리해서 내용을 파악해야 함
- 이동할 때 공원 벗어나는지 + 장애물 만나는지 파악해야 함
  - 둘 중 하나라도 해당되면 그 명령은 건너뛰고 다음 명령 실행
- 마지막 반환은 `[세로 방향 좌표, 가로 방향 좌표]`

> [!success] 잘한 점
> - 문제의 새 요소를 거의 다 스스로 찾아냄 → **문제 읽기 실력이 좋아짐**
> - "하나라도 걸리면 명령 전체 무시" 조건을 정확히 파악
> - 반환 순서 `[세로, 가로]`를 놓치지 않음

---

## 풀이 과정

### 1차 ❌ 시작 지점 찾기 + 전체 틀
```python
for a in range(park):
    for b in range(park[a]):
        if b == "S":
            start = park[a][b]
```
```python
direct = ("E": (0, 1), "S": (-1, 0), "W": (0, -1), "N": (1, 0))
```
- `range(park)` → range 안에 리스트를 넣음
- `b == "S"` → **번호**를 문자와 비교 (값 vs 좌표)
- `start = park[a][b]` → 위치가 아니라 **문자 "S"**가 저장됨
- 딕셔너리를 `( )`로 만듦, N/S 부호 반대
- routes를 이중 for문으로 글자 하나씩 쪼갬
- 칠할 필요 없는데 check 판을 따로 만듦

### 2차 ❌ split 도입, 명령을 따로 저장하려 함
```python
for p in park:
    for pi in park[p]:
        if park[p][pi] == "S":
            start = [p, pi]

for r in routes:
    d_num = r.split()

for i in range(0, len(d_num), 2):
    word = {d_num[i]: d_num[i + 1]}

for i in word:
    dx, dy = move[i] * word[i]
```
- `for p in park` → p에 번호가 아니라 **문자열 한 줄**이 들어옴
- `d_num = r.split()` → 반복마다 **덮어써서** 마지막 명령만 남음
- 딕셔너리는 같은 키를 두 번 못 가짐 → "E" 명령이 두 번이면 하나 사라짐
- `(0, 1) * 2` → `(0, 2)`가 아니라 `(0, 1, 0, 1)` (튜플 **반복**)
- word의 값 `'2'`는 문자
- **한 번에 n칸 점프**하면 가는 길 중간의 장애물을 못 봄

> [!tip] 방향 전환
> 명령을 따로 저장했다가 나중에 처리하지 말고, **명령 하나를 꺼내자마자 그 자리에서 이동까지 처리**

### 3차 ❌ 시작 위치·split 성공, 이동 부분에서 막힘
```python
for p in range(len(park)):
    for pi in range(len(park[p])):
        if park[p][pi] == "S":
            start = [p, pi]          # ✅ 성공
        if park[p][pi] == "X":
            danger = [p, pi]         # ❌ X가 여러 개면 마지막만 남음

for r in routes:
    k, v = r.split()                 # ✅ 성공
    nh, nw = start + move[k]         # ❌ 리스트 + 튜플
    for a in range(v):               # ❌ v는 문자
        if [nh, nw] != danger:
            H, W = nh, nw
            start = [H, W]           # ❌ 한 칸 갈 때마다 바로 이동
```

> [!question] 내 질문
> "N과 S 방향 값은 반환할 때 H를 먼저 반환해야 해서 저게 맞지 않나?"

> [!tip] 답
> **순서(앞 = 세로, 뒤 = 가로)는 맞음. 부호가 반대였음.**
> 2차원 리스트는 **0번째 행이 맨 위** → 북쪽(위)으로 가면 행 번호가 **줄어듦**
> → N = `(-1, 0)`, S = `(1, 0)`

> [!warning] 이 문제의 핵심 함정
> "E 3"에서 세 번째 칸이 X라면? 한 칸 갈 때마다 바로 이동하면 이미 두 칸 움직인 상태.
> 문제는 **명령 전체를 무시** → 제자리여야 함
> → **임시 위치로 끝까지 먼저 걸어보고, 전부 통과했을 때만 진짜 이동**

### 4차 ❌ 방향·시작 위치 완벽, 줄 위치와 조건이 문제
```python
nh, nw = H, W                        # ❌ routes 반복문 밖 → 실패한 명령의 임시 위치가 이어짐
for r in routes:
    k, v = r.split()
    nh, nw = nh + move[k][0], nw + move[k][1]   # ✅ 값 하나씩 더하기는 정답! ❌ 위치가 반복문 밖
    for _ in range(v):
        if -n <= park[nh, nw] <= n or park[nh, nw] != "X":   # ❌ 값 vs 좌표, or, 문법
            H, W = nh, nw
```
- 한 칸 이동 줄이 칸 수 반복문 **밖** → 명령당 한 칸만 이동
- `park[nh, nw]` → `park[nh][nw]`가 맞는 문법
- 범위 검사에서 칸의 **값**을 숫자와 비교 (값 vs 좌표 재발 ⚠️)
- park는 인덱스가 **0부터** → 음수 범위 아님, 세로·가로 길이도 다를 수 있음
- `or` → 공원 밖이지만 X가 아니면 통과해버림
- `ok` 깃발 / `break` 없음

### 5차 (빈칸 채우기) ❌ → 성공
- 빈칸 ① `len(rows)` → rows는 숫자라 len 불가 → `len(park[0])`
- 빈칸 ③ `park[0][0] > park[nh][nw]` → 또 **값끼리 비교** → 좌표 숫자로 비교해야 함
- `int(v)`, 빈칸 ④는 처음부터 정답 ✅

## 최종 코드 (통과) 🎉
```python
def solution(park, routes):
    rows = len(park)                 # 세로 길이
    cols = len(park[0])              # 가로 길이
    move = {"E": (0, 1), "S": (1, 0), "W": (0, -1), "N": (-1, 0)}

    # 1. 시작 위치 찾기
    for p in range(rows):
        for pi in range(cols):
            if park[p][pi] == "S":
                H, W = p, pi

    # 2. 명령 하나씩 처리
    for r in routes:
        k, v = r.split()             # k: 방향, v: 칸 수 (문자)
        nh, nw = H, W                # 명령마다 진짜 위치에서 임시 출발
        ok = True                    # 일단 갈 수 있다고 가정

        for _ in range(int(v)):      # 한 칸씩 v번
            nh, nw = nh + move[k][0], nw + move[k][1]
            if not (0 <= nh < rows and 0 <= nw < cols) or park[nh][nw] == "X":
                ok = False           # 공원 밖이거나 장애물
                break                # 더 볼 필요 없음

        if ok:                       # 전부 통과했을 때만
            H, W = nh, nw            # 진짜 이동

    return [H, W]
```

### 조금 더 다듬은 버전 (참고)
```python
def solution(park, routes):
    rows, cols = len(park), len(park[0])
    move = {"E": (0, 1), "S": (1, 0), "W": (0, -1), "N": (-1, 0)}

    for i in range(rows):
        if "S" in park[i]:
            h, w = i, park[i].index("S")    # 문자열에서 위치 바로 찾기

    for route in routes:
        op, n = route.split()
        dh, dw = move[op]                   # 튜플 언패킹
        nh, nw = h, w
        for _ in range(int(n)):
            nh, nw = nh + dh, nw + dw
            if not (0 <= nh < rows and 0 <= nw < cols) or park[nh][nw] == "X":
                break
        else:                               # break 없이 끝났을 때만 실행
            h, w = nh, nw

    return [h, w]
```
- `"S" in park[i]`, `park[i].index("S")` → 문자열에서 글자 위치 바로 찾기
- `for ... else` → **break 없이 반복이 끝났을 때만** else 실행 → ok 깃발 대신 쓸 수 있음
- 지금은 ok 깃발 방식이 더 읽기 쉬우니 그걸로 충분!

### 복잡도
- 시간: **O(H·W + R·M)** (H·W = 시작 위치 찾기, R = 명령 수, M = 최대 이동 칸 수)
- 공간: **O(1)**

## 틀렸던 부분 한눈에 보기

| 실수 | 왜 틀렸나 | 바른 방법 |
|---|---|---|
| `range(park)` | range 안에는 숫자 | `range(len(park))` |
| `for p in park` 로 위치 찾기 | p에 **값**(문자열 한 줄)이 들어옴 | 번호가 필요하면 `range(len(...))` |
| `b == "S"` / `start = park[a][b]` | 번호를 문자와 비교 / 위치 대신 문자 저장 | `park[a][b] == "S"` / `H, W = a, b` |
| 딕셔너리를 `( )`로 | 문법 오류 | `{ }` |
| N/S 부호 반대 | 0번째 행이 맨 위 | N `(-1, 0)`, S `(1, 0)` |
| 반복문 안에서 `=`로 저장 | 덮어쓰기 → 마지막만 남음 | 꺼내자마자 바로 처리 |
| `danger = [p, pi]` | X가 여러 개면 마지막만 남음 | `park[nh][nw] == "X"`로 바로 확인 |
| `(0, 1) * 2` | 튜플 **반복** → `(0, 1, 0, 1)` | 값을 하나씩 꺼내 계산 |
| `start + move[k]` | 리스트 + 튜플 에러 / 리스트끼리는 **이어붙이기** | `nh + move[k][0]`, `nw + move[k][1]` |
| `range(v)` | v는 문자 | `int(v)` |
| 한 번에 n칸 점프 | 중간 장애물을 못 봄 | **한 칸씩 n번** |
| 한 칸마다 바로 이동 | 중간에 막혀도 이미 움직임 | 임시 위치 + `ok` 깃발 + `break` |
| 임시 위치 초기화가 반복문 밖 | 실패한 명령의 위치가 이어짐 | 명령마다 `nh, nw = H, W` |
| 한 칸 이동 줄이 칸 수 반복문 밖 | 명령당 한 칸만 이동 | 칸 수 반복문 **안**으로 |
| `park[nh, nw]` | 문법 오류 | `park[nh][nw]` |
| 범위 검사에 **칸의 값** 사용 | 값 vs 좌표 혼동 (총 3번 재발 ⚠️) | `nh`, `nw` 숫자 자체를 비교 |
| `-n <= ... <= n` | park 인덱스는 0부터 | `0 <= nh < rows` |
| `len(rows)` | rows는 숫자 | `len(park[0])` |
| `or`로 범위·장애물 연결 (이동 조건) | 하나만 만족해도 이동 | 이동 조건은 `and` / 막는 조건은 `or` |

## 핵심 개념 정리

> [!important] 1. 값 vs 좌표 ⚠️⚠️⚠️ (가장 많이 반복된 실수)
> - `nh` → 위치 **번호**
> - `park[nh][nw]` → 그 위치의 **값** ("S", "O", "X")
> - **범위 검사에는 `park[...]`가 절대 안 나온다!** 오직 nh, nw만
> - 코드 쓸 때마다 자문: "이 변수는 번호야, 값이야?"

> [!important] 2. 임시 위치 + 깃발 변수 (이 문제의 핵심)
> ```python
> nh, nw = H, W        # 임시 위치
> ok = True            # 깃발: 일단 가능하다고 가정
> for _ in range(n):
>     한 칸 이동
>     if 문제 발생:
>         ok = False
>         break        # 즉시 탈출
> if ok:
>     H, W = nh, nw    # 전부 통과했을 때만 진짜 이동
> ```
> "전부 통과해야 반영" 조건이 나오면 이 패턴!

> [!important] 3. 2차원 리스트의 방향
> - 0번째 행이 **맨 위** → 위로 가면 행 번호 감소
> - N `(-1, 0)`, S `(1, 0)`, W `(0, -1)`, E `(0, 1)`
> - 수학 좌표(y가 위로 증가)와 반대!

> [!important] 4. 범위 밖 검사 + 단락 평가
> ```python
> if not (0 <= nh < rows and 0 <= nw < cols) or park[nh][nw] == "X":
> ```
> - `or`는 앞이 참이면 **뒤를 실행 안 함** → 공원 밖이면 `park[nh][nw]`에 접근조차 안 함
> - 그래서 **범위 검사가 항상 먼저**

> [!important] 5. 리스트/튜플 연산 함정
> - `[1, 0] + [0, 1]` → `[1, 0, 0, 1]` (이어붙이기)
> - `(0, 1) * 2` → `(0, 1, 0, 1)` (반복)
> - 좌표 덧셈은 **값을 하나씩 꺼내서**

> [!important] 6. 반복문 안의 `=`는 덮어쓰기
> 여러 개를 모으려면 `append`, 아니면 **꺼내자마자 바로 처리**

> [!important] 7. 문자열 처리
> ```python
> op, n = "E 2".split()   # op = "E", n = "2" (문자!)
> int(n)                  # 2
> ```

> [!important] 8. 세로·가로 길이
> - 세로 `len(park)`, 가로 `len(park[0])`
> - 정사각형이 아닐 수 있으니 따로 구하기

## 공부해야 할 부분
- [ ] **값 vs 좌표** — 안전지대, 공원 산책에서 총 3번 이상 반복. 최우선 점검 대상
- [ ] **임시 위치 + 깃발 + break** 패턴 손에 익히기
- [ ] 리스트/튜플의 `+`, `*` 동작 (`print`로 직접 실험해보기)
- [ ] 반복문 안 = 덮어쓰기 vs `append`
- [ ] 코드 줄의 **위치**(반복문 안/밖)에 따라 실행 횟수가 달라진다는 감각
- [ ] (선택) `for ... else`, `str.index()`
- [ ] 3일 뒤 **안 보고 다시 풀기**

## 회고
- 문제 분석(새 요소 찾기)은 처음부터 거의 완벽 → 확실한 성장
- 막힌 곳은 대부분 **로직이 아니라 문법 도구와 값/좌표 구분**
- `move[k][0]`처럼 값을 하나씩 꺼내 더하기, `int(v)`, 빈칸 ④는 스스로 정답 → 번역 능력은 탄탄함
- "임시로 끝까지 걸어보고 반영"이라는 패턴은 처음 봤지만 의사코드를 보고 바로 이해함
