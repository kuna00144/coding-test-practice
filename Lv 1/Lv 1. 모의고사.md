# 모의고사 (프로그래머스 Lv.1)

## 문제 요약
- 수포자 3명이 각자 정해진 **패턴을 반복**해서 찍음
- 정답 리스트 `answers`가 주어질 때, **가장 많이 맞힌 사람**의 번호를 리스트로 반환
- 최고 점수가 여러 명이면 **전부**, 번호 **오름차순**으로
- `answers`는 최대 10,000개 → 패턴이 수천 바퀴 반복될 수 있음

> [!info] 유형
> 완전탐색 (모든 문제 × 모든 사람 다 비교) / **반복 패턴 = 나머지 연산 `%`** / 최댓값을 가진 것 **모두** 고르기
> 격자·위치 문제에서 처음으로 벗어난 유형

---

## 1차 분석 (패턴 파악)
- 1번 수포자: `1, 2, 3, 4, 5` 반복
- 2번 수포자: 짝수 번째(0부터)는 전부 2, 홀수 번째는 `1, 3, 4, 5` 반복
  → 합치면 `2, 1, 2, 3, 2, 4, 2, 5`
- 3번 수포자: `3, 1, 2, 4, 5`를 각각 2개씩 순서대로 반복
  → `3, 3, 1, 1, 2, 2, 4, 4, 5, 5`
- 계획: 패턴을 저장 → answers 개수만큼 비교 → max로 최고 점수 → 동점이면 다 포함, 오름차순

> [!success] 잘한 점
> - 세 사람의 패턴을 **정확히** 분석 (특히 2번의 짝수/홀수 분리)
> - 전체 설계를 혼자 완성
> - 모르는 문법(딕셔너리 최댓값)을 **검색해서 해결**, 그중 **동점자를 모두 찾는 방법**을 골라서 적용 → 문제 조건에 맞는 도구 선택

> [!note] 사진 내용 요약
> **방법 2: `max(딕셔너리, key=딕셔너리.get)`**
> - 값(value)이 가장 큰 **키 하나**를 돌려줌
> - ⚠️ 최댓값이 여러 개면 **처음 발견된 하나만** 반환 → 이 문제엔 부적합
>
> **방법 3: 최댓값을 가진 키 모두 찾기**
> ```python
> max_val = max(my_dict.values())
> max_keys = [k for k, v in my_dict.items() if v == max_val]
> ```
> → 이 문제처럼 **동점자를 모두** 골라야 할 때 사용

## 풀이 과정

### 1차 ❌ 패턴 인덱스가 범위를 넘어감
```python
for i in range(n):
    if answers[i] == one[i]:
        s["1"] += 1
    ...
```
- 예시(answers 5개)는 통과하지만, answers가 **6개 이상**이면 `one[5]`에서 에러
- 패턴은 **반복**되니까 길이를 넘어가면 다시 0부터 세야 함

### 2차 ❌ 한 번만 빼서 되돌리기
```python
one_j, two_j, three_j = i                  # ❌ 숫자 하나를 세 변수에 언패킹 불가
if one_j > len(one):                        # ❌ i == 5 일 때 걸러지지 않음
    one_j = i - (len(one) - 1)              # ❌ 되돌린 위치가 틀림
```
- `i = 5` → 원래 0이어야 하는데 `5 - 4 = 1`
- `i = 9` → `9 - 4 = 5`로 또 범위 밖 → **한 번 빼는 걸로는 부족**

### 3차 ❌ 카운터 변수로 공식 만들기
```python
if one_j == len(one):
    one_j = i // oc - (len(one) - 1)
    oc += 1
```
- == 라서 **딱 i = 5일 때만** 되돌리고, i = 6부터는 처리 안 됨 → `one[6]` 에러
- 직접 공식을 만들수록 점점 복잡해짐 → **도구(나머지 연산)가 필요한 신호**

### 4차 → 성공 🎉 나머지 연산 `%`
```python
one[i % len(one)]
```
- if문, 인덱스 변수, 카운터가 **전부 사라짐**

## 최종 코드 (통과)
```python
def solution(answers):
    n = len(answers)
    s = {"1": 0, "2": 0, "3": 0}               # 수포자별 점수
    one = [1, 2, 3, 4, 5]
    two = [2, 1, 2, 3, 2, 4, 2, 5]
    three = [3, 3, 1, 1, 2, 2, 4, 4, 5, 5]
    answer = []

    for i in range(n):
        if answers[i] == one[i % len(one)]:      # 패턴 반복 = 나머지 연산
            s["1"] += 1
        if answers[i] == two[i % len(two)]:
            s["2"] += 1
        if answers[i] == three[i % len(three)]:
            s["3"] += 1

    max_val = max(s.values())                  # 최고 점수

    for k, v in s.items():                     # 최고 점수인 사람 전부
        if v == max_val:
            answer.append(int(k))
    return answer
```

### 다듬은 버전 (참고)
```python
def solution(answers):
    patterns = [[1, 2, 3, 4, 5],
                [2, 1, 2, 3, 2, 4, 2, 5],
                [3, 3, 1, 1, 2, 2, 4, 4, 5, 5]]
    scores = [0, 0, 0]

    for i, ans in enumerate(answers):          # 인덱스와 값을 함께 꺼내기
        for p in range(3):                     # 세 사람을 반복문으로
            if ans == patterns[p][i % len(patterns[p])]:
                scores[p] += 1

    max_val = max(scores)
    return [p + 1 for p in range(3) if scores[p] == max_val]
```
바뀐 점:
- 패턴을 **리스트 하나**에 모으고 사람도 반복문으로 → if 세 개가 하나로 (사람이 늘어나도 코드는 그대로)
- 키를 문자열 `"1"`로 두고 `int(k)` 변환하는 대신, **인덱스 + 1**로 사람 번호 계산
- `enumerate(answers)` → `i`와 `answers[i]`를 동시에 꺼냄
- 마지막 반복문을 **리스트 컴프리헨션**으로 (사진의 방법 3과 같은 문법)

### 복잡도
- 시간: **O(N)** (N = answers 길이, 문제마다 3명 비교 → 상수배)
- 공간: **O(1)** (패턴과 점수는 고정 크기)

## 틀렸던 부분 한눈에 보기

| 실수 | 왜 틀렸나 | 바른 방법 |
|---|---|---|
| `one[i]` | 패턴 길이보다 i가 커지면 범위 밖 | `one[i % len(one)]` |
| `a, b, c = i` | 숫자 하나는 여러 변수로 언패킹 불가 | `a = b = c = i` 또는 `a, b, c = i, i, i` |
| `> len(one)` | 인덱스 5는 이미 범위 밖인데 `5 > 5`는 거짓 | 경계는 `>=` (애초에 `%`면 불필요) |
| `i - (len - 1)` | 되돌린 위치가 1칸 어긋남 + 한 번만 뺌 | 나머지 연산 |
| `==`로 한 번만 되돌림 | i = 6부터는 처리 안 됨 | 나머지 연산 |
| 공식을 직접 만들며 복잡해짐 | 도구를 몰라서 우회 | **"반복·순환" = `%`** 를 떠올리기 |

## 핵심 개념 정리

> [!important] 1. 반복 패턴 = 나머지 연산 `%`
> ```python
> pattern[i % len(pattern)]
> ```
> - `%`의 결과는 항상 **0 ~ (나누는 수 − 1)** → 항상 패턴 안
> - i가 아무리 커도 올바른 위치를 가리킴
> - [[Lv 0. 공 던지기]]의 `(idx + 2) % n`과 **같은 원리** (원형 순회)
>
> | i | 0 | 4 | 5 | 6 | 12 | 9999 |
> |---|---|---|---|---|---|---|
> | `i % 5` | 0 | 4 | 0 | 1 | 2 | 4 |

> [!important] 2. 최댓값을 가진 것 **모두** 고르기
> ```python
> max_val = max(scores)
> [i for i in range(len(scores)) if scores[i] == max_val]
> ```
> - `max(dict, key=dict.get)`은 **하나만** 반환 → 동점자 처리 불가
> - "가장 ~한 것을 **모두**" 조건이 나오면 → 최댓값 먼저 구하고, 같은 것 전부 모으기

> [!important] 3. 딕셔너리 순회
> - `d.values()` → 값들만
> - `d.items()` → `(키, 값)` 쌍 → `for k, v in d.items():`
> - 딕셔너리는 **넣은 순서**를 유지 → 1, 2, 3 순으로 넣었으니 오름차순이 자동으로 지켜짐

> [!important] 4. 언패킹 규칙
> - `a, b = (1, 2)` → 오른쪽 값 개수 = 왼쪽 변수 개수
> - `a, b, c = 5` → ❌ (값이 하나뿐)
> - 같은 값을 여러 변수에: `a = b = c = 5`

> [!important] 5. 직접 공식이 복잡해지면 멈추고 생각하기
> 카운터를 추가하고 if를 늘려도 계속 틀리면 → **이미 있는 도구**(`%`, 내장 함수)가 있을 가능성이 높음

> [!important] 6. `enumerate`
> ```python
> for i, ans in enumerate(answers):   # i = 인덱스, ans = 값
> ```
> 인덱스와 값이 **둘 다** 필요할 때

## 공부해야 할 부분
- [ ] **"반복된다 / 돌아온다 / 순환한다" → `%`** 연결 (공 던지기에 이어 두 번째. 이번엔 힌트를 두 번 받고서야 사용)
- [ ] 동점자를 모두 고르는 패턴 (max → 같은 것 모으기)
- [ ] 리스트 컴프리헨션 기본 문법
- [ ] `enumerate`
- [ ] 같은 형태의 if가 반복되면 → 데이터를 리스트로 묶고 반복문으로
- [ ] 3일 뒤 **안 보고 다시 풀기**

## 회고
- 패턴 분석과 전체 설계는 **처음부터 혼자** 완성 → [[Lv 1. 키패드 누르기]]에 이어 설계력 안정적
- 모르는 문법을 **검색해서 찾고, 문제 조건(동점자 모두)에 맞는 방법을 골라낸** 것 → 실전에서도 중요한 능력
- 막힌 곳은 "반복 패턴 처리" 한 가지 → 공 던지기 노트에 있던 `%`를 바로 연결하지 못함
  → 노트를 쓰는 것만큼 **비슷한 상황에서 노트를 떠올리는 것**이 중요
- 직접 공식을 만들수록 복잡해졌던 경험 → "복잡해지면 도구를 의심하자"
