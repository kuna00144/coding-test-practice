# [SWEA D2] 1961. 숫자 배열 회전

> [!NOTE]
> 문제 원문과 입출력 예시는 SW Expert Academy 저작물이라 이 노트에 옮기지 않았습니다.
> 문제는 SWEA 사이트에서 **문제 번호 1961**로 검색해 확인하세요.

## 문제 핵심 (내 말로 한 줄)
- 입력으로 받은 N×N 배열을 **90도, 180도, 270도** 시계 방향으로 돌린 결과를 한 줄씩 나란히 출력

## 유형
- 구현 / **2차원 배열 회전** (삼성 계열 시험 단골 기본기)
- 출력 형식이 독특한 문제 (한 줄에 세 회전 결과를 나란히)

---

## 풀이 과정

> [!TIP]
> **처음으로 힌트 없이 끝까지 간 문제**
> - 약 3시간 걸림 → 시간은 길었지만 **회전 공식을 혼자 찾아냄**
> - 90 / 180 / 270도를 "90도를 세 번 반복"으로 해결하는 발상도 스스로

### 내가 찾은 핵심: 90도 회전 공식
```python
new_board[i][j] = board[N - 1 - j][i]
```
3×3으로 확인하면:

| 회전 후 칸 `(i, j)` | 원래 칸 `(N-1-j, i)` | 값 |
|---|---|---|
| (0, 0) | (2, 0) | 7 |
| (0, 1) | (1, 0) | 4 |
| (0, 2) | (0, 0) | 1 |
| (1, 0) | (2, 1) | 8 |

→ 회전 후 **첫 줄 = 원래 첫 열을 아래에서 위로** 읽은 것 (7 4 1)

### 1차 ❌ 검색해서 가져온 board 줄
```python
board = [[i * N + j + 1 for j in range(N)] for i in range(N)]
```
- 이건 **1부터 N²까지 숫자로 판을 직접 만드는** 코드
- 이 문제는 **회전할 판을 입력으로 줌** → 입력 판을 읽지 않고 엉뚱한 판을 돌림
- 첫 테스트케이스가 마침 `1 2 3 / 4 5 6 / 7 8 9`라서 **우연히 맞아 보였음**
- 실제 입력에선 판 줄을 아무도 안 읽으니 → 다음 `int(input())`이 `"1 2 3"`을 읽어 에러
- 로컬 `input.txt`에 판 줄 없이 N만 넣어서 테스트 → 버그가 안 드러남

### 1차 ❌ answer의 칸 수
```python
answer = [[0] * N for _ in range(N)]     # 한 줄에 N칸
```
- 실제로 채우는 건 90 / 180 / 270 → **3칸**
- N = 3일 땐 N칸 = 3칸이라 우연히 OK
- N = 6이면 6칸 중 3칸만 채워지고 나머지는 숫자 `0`
- 출력에서 `map(str, 0)` → `TypeError: map argument #1 must support iteration`

### 2차 → 성공 🎉
- board → 입력 패턴 ④로 **입력에서 읽기**
- answer → 한 줄에 **3칸**

---

## 최종 코드
```python
# import sys
# sys.stdin = open("input.txt", "r")   # 로컬 테스트용 — 제출 전 주석 처리!

T = int(input())

for test_case in range(1, T + 1):
    N = int(input())
    board = [list(map(int, input().split())) for _ in range(N)]   # 입력 패턴 ④
    answer = [[0] * 3 for _ in range(N)]     # 줄마다 [90도, 180도, 270도]

    for a in range(3):                       # 90도씩 세 번 돌리기
        new_board = [[0] * N for _ in range(N)]
        for i in range(N):
            for j in range(N):
                new_board[i][j] = board[N - 1 - j][i]   # 시계 방향 90도
            answer[i][a] = new_board[i]      # i번째 줄을 a번째 회전 결과로 저장
        board = new_board                    # 돌린 판을 다음 회전의 기준으로

    print(f"#{test_case}")
    for row in answer:
        print(" ".join("".join(map(str, group)) for group in row))
```

### 출력 줄 풀어보기
```python
row = [[7, 4, 1], [9, 8, 7], [3, 6, 9]]     # i번째 줄의 90 / 180 / 270 결과

"".join(map(str, [7, 4, 1]))              # "741"   ← 숫자를 붙여서
" ".join(["741", "987", "369"])           # "741 987 369"   ← 사이에 공백
```

### 복잡도
- 시간: **O(N²)** (회전 3번 × N²칸), 공간: **O(N²)**

## 다듬은 버전 (참고)

### 회전 함수로 분리
```python
def rotate(board, N):
    return [[board[N - 1 - j][i] for j in range(N)] for i in range(N)]

T = int(input())
for test_case in range(1, T + 1):
    N = int(input())
    board = [input().split() for _ in range(N)]   # 출력만 하니 문자열 그대로 둬도 됨
    r90 = rotate(board, N)
    r180 = rotate(r90, N)
    r270 = rotate(r180, N)

    print(f"#{test_case}")
    for i in range(N):
        print("".join(r90[i]), "".join(r180[i]), "".join(r270[i]))
```
- 회전을 **함수 하나**로 → 같은 공식을 재사용, 읽기 쉬움
- 계산이 없고 출력만 하므로 `int`로 바꾸지 않고 **문자열 그대로** → `map(str, ...)` 불필요
- `print(a, b, c)`는 자동으로 공백을 넣어줌

### 파이썬 관용구 (알아만 두기)
```python
rotated = [list(row) for row in zip(*board[::-1])]   # 시계 방향 90도
```
- `board[::-1]` 위아래 뒤집기 → `zip(*...)` 행과 열 바꾸기 = 시계 방향 90도
- 짧지만 시험장에서 헷갈리면 **직접 공식**이 더 안전

## 틀렸던 부분 한눈에 보기

| 실수 | 왜 틀렸나 | 바른 방법 |
|---|---|---|
| 검색한 board 생성 코드 사용 | 입력을 안 읽고 1~N²로 판을 만듦 | 입력 패턴 ④로 읽기 |
| 판 줄 없는 `input.txt`로 테스트 | 실제 입력과 달라서 버그가 숨음 | **문제의 입력 예시 전체**로 테스트 |
| `answer`를 N×N으로 | 실제 필요한 칸은 3개 | `[[0] * 3 for _ in range(N)]` |
| 첫 케이스만 보고 "거의 다 됨" | N = 3이 우연히 두 버그를 가림 | **크기가 다른 케이스**까지 확인 |

## 핵심 개념 정리

> [!IMPORTANT]
> **1. 시계 방향 90도 회전 공식**
> `new[i][j] = old[N - 1 - j][i]`
> - 회전 후 첫 줄 = 원래 첫 열을 **아래에서 위로**
> - 180도 = 90도 두 번, 270도 = 90도 세 번
> - 공식이 헷갈리면 **3×3을 그려서 몇 칸만 확인**

> [!IMPORTANT]
> **2. 검색한 코드는 작은 값으로 찍어보고 쓰기**
> `board = [[i * N + j + 1 ...]]`를 N = 3으로 `print` 해봤다면
> "입력과 상관없이 항상 1~9가 나온다"는 걸 바로 알 수 있었음

> [!IMPORTANT]
> **3. 테스트는 실제 입력 예시 전체로**
> - 직접 만든 간단한 입력은 버그를 숨길 수 있음
> - 특히 **N = 3처럼 작은 값은 우연히 맞는 경우**가 많음
> - 크기가 다른 케이스(N = 6, 7)까지 통과하는지 확인

> [!IMPORTANT]
> **4. 에러 메시지 + 출력을 함께 보기**
> `TypeError: map argument #1 must support iteration`
> → "반복할 수 없는 값(숫자 0)에 map을 썼다"
> → 출력에서 **어떤 케이스부터** 깨졌는지 보면 원인(N이 3보다 클 때)이 보임

> [!IMPORTANT]
> **5. 우연히 맞는 값을 의심하기**
> N = 3이고 회전도 3번이라 `[0] * N`과 `[0] * 3`이 같았음
> → 숫자가 **우연히 같은 두 값**은 코드에서 헷갈리기 쉬움. 의미가 다르면 따로 쓰기

- [ ] 로컬 테스트는 **문제의 입력 예시 전체**로
- [ ] 첫 케이스만 맞았을 때 "거의 다 됐다"고 판단하지 않기
