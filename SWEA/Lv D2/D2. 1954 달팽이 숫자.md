# [SWEA D2] 1954. 달팽이 숫자

> [!NOTE]
> 문제 원문과 입출력 예시는 SW Expert Academy 저작물이라 이 노트에 옮기지 않았습니다.
> 문제는 SWEA 사이트에서 **문제 번호 1954**로 검색해 확인하세요.

## 문제 핵심 (내 말로 한 줄)
- N×N 격자에 1부터 숫자를 **바깥에서 안쪽으로 시계 방향으로 돌면서** 채우기

## 유형
- 시뮬레이션 (위치와 방향을 직접 관리)
- 방향 전환 / 범위 검사 / 방문 체크 / **나머지 연산으로 방향 순환**
- [[Lv 1. 공원 산책]]의 "다음 위치 계산 → 검사 → 이동" + **방향 바꾸기**

---

## 1차 분석
- N을 입력받아야 함
- board를 만들어서 안을 전부 0으로 채움
- (0, 0)부터 시작해서 **벽을 만나거나 0이 아닌 값을 만나면** 방향을 바꿔서 이동

> [!TIP]
> 잘한 점
> - "0으로 채운 판 → (0, 0) 시작 → 벽 또는 이미 채운 칸에서 방향 전환"이라는 **핵심 규칙을 처음부터 정확히 파악**
> - 0이 아닌 칸 = 이미 방문한 칸 → **값으로 방문 체크**하는 발상

---

## 풀이 과정

### 1차 ❌ 이중 for문으로 위치를 정함
```python
for i in range(N):
    for j in range(N):
        for k in range(4):
            ni, nj = i + di[k], j + dj[k]
            if board[ni][nj] != 0 and 0 <= ni < N and 0 <= nj < N:
                board[i][j] = nb
        nb += 1
print(f"# {test_case} {board}")
```
- 이중 for문은 **항상 줄 단위**로 방문 → 꺾어 도는 순서를 만들 수 없음
- 방향 리스트 순서가 오른쪽, 왼쪽, 위, 아래 → "다음 방향"으로 넘어갈 수 없음
- board를 범위 검사보다 먼저 확인, 조건도 반대
- 출력: `#` 뒤 공백 + 리스트 모양 그대로 출력
- 숫자를 0부터 채움

> [!IMPORTANT]
> **"for문이 위치를 정하는 게 아니라, 내가 위치를 들고 다닌다"**
> 위치 변수 `(x, y)` + 방향 변수 `k`를 상태로 유지하며 한 칸씩 이동

### 2차 ❌ 위치 변수 도입, 세부에서 걸림
```python
d = {0: (1, 0), 1: (0, -1), 2: (-1, 0), 3: (0, 1)}
x, y = 0, 0
for i in range(1, N ** 2 + 1):
    board[x][y] = i
    k = 0                                   # ❌ 반복마다 방향 리셋
    nx, ny = d[k][0] + x, d[k][1] + y
    if board[nx][ny] == 0 or 0 > nx or nx > N or 0 > ny or ny > N:   # ❌
        k += 1                              # ❌ 3 다음 4
        ...
print(f"# {test_case}")                     # ❌ 공백
```
- ✅ 위치 변수 `x, y`, 반복 횟수 `N ** 2`, 격자 출력 방식 → 큰 구조는 해결
- `board[x][y]`에서 x는 **행** → `(1, 0)`은 오른쪽이 아니라 **아래**
- `k = 0`이 반복문 **안** → 방향을 바꿔도 다음 칸에서 다시 오른쪽으로 리셋 ([[D2. 2001 파리 퇴치]] "초기화 위치가 곧 의미")
- `k += 1` → 3 다음 4가 되어 `d[4]` 에러
- 비어 있을 때(`== 0`) 방향을 바꿈 → 반대. 바꿔야 할 때는 **이미 채워졌을 때**
- `nx > N` → 인덱스 N도 범위 밖인데 통과
- board를 범위 검사보다 **먼저** 확인

### 3차 ❌ 방향 순서 반대 + 직접 공식
```python
d = {0: (0, 1), 1: (-1, 0), 2: (0, -1), 3: (1, 0)}   # 오른쪽 → 위 ❌
k = 0                                                 # ✅ 반복문 밖으로
...
if k % (N + 1) == 0:                                  # ❌ 직접 만든 공식
    k = k - N + 1
if board[nx][ny] != 0 or not(0 <= nx < N and 0 <= ny < N):   # ❌ 순서
```
- 오른쪽 다음이 **위** `(-1, 0)` → 시계 방향은 오른쪽 → **아래** → 왼쪽 → 위
- 방향은 N과 상관없이 **항상 4개**인데 공식에 N이 들어감
- `or` 앞쪽에서 board를 먼저 접근 → 범위 밖이면 에러

### 4차 ❌ 공식만 남음
```python
if k % 3 == 0:
    k = k - 3
```
- 처음 `k = 0` → `0 % 3 == 0` 참 → `k = -3` → `d[-3]` **키 에러**
- 숫자 1을 쓰자마자 문제 발생

> [!WARNING]
> **[[Lv 1. 모의고사]]와 똑같은 패턴으로 막힘**
> "3 다음에 0으로 돌아가기"를 직접 공식으로 만들려다 점점 복잡해짐
> → 답은 `%` 한 줄: `k = (k + 1) % 4`

### 5차 → 성공 🎉

## 최종 코드
```python
# import sys
# sys.stdin = open("input.txt", "r")   # 로컬 테스트용 — 제출 전 주석 처리!

T = int(input())

for test_case in range(1, T + 1):
    N = int(input())
    board = [[0] * N for _ in range(N)]                  # 0 = 아직 안 채운 칸
    d = {0: (0, 1), 1: (1, 0), 2: (0, -1), 3: (-1, 0)}   # 오른쪽, 아래, 왼쪽, 위 (시계 방향)
    x, y = 0, 0                                          # 지금 위치
    k = 0                                                # 지금 방향 (케이스마다 한 번 초기화)

    for i in range(1, N ** 2 + 1):                       # 1부터 N²까지
        board[x][y] = i
        nx, ny = d[k][0] + x, d[k][1] + y                # 다음 위치 계산

        if not(0 <= nx < N and 0 <= ny < N) or board[nx][ny] != 0:   # 범위 밖 or 이미 채움
            k = (k + 1) % 4                              # 다음 방향 (3 다음 0)
            nx, ny = d[k][0] + x, d[k][1] + y            # 다음 위치 다시 계산
        x, y = nx, ny                                    # 이동

    print(f"#{test_case}")
    for row in board:
        print(*row)
```

### 손으로 따라가기 (N = 3)
| 숫자 | 위치 | 방향 k | 다음 칸 | 판단 |
|---|---|---|---|---|
| 1 | (0,0) | 0 → | (0,1) | 이동 |
| 2 | (0,1) | 0 → | (0,2) | 이동 |
| 3 | (0,2) | 0 → | (0,3) 범위 밖 | **k = 1** ↓ (1,2) |
| 4 | (1,2) | 1 ↓ | (2,2) | 이동 |
| 5 | (2,2) | 1 ↓ | (3,2) 범위 밖 | **k = 2** ← (2,1) |
| 6 | (2,1) | 2 ← | (2,0) | 이동 |
| 7 | (2,0) | 2 ← | (2,-1) 범위 밖 | **k = 3** ↑ (1,0) |
| 8 | (1,0) | 3 ↑ | (0,0) 이미 채움 | **k = 0** → (1,1) |
| 9 | (1,1) | — | — | 끝 |

### 복잡도
- 시간: **O(N²)** (칸마다 한 번씩), 공간: **O(N²)**

## 다듬은 버전 (참고)
```python
T = int(input())
for test_case in range(1, T + 1):
    N = int(input())
    board = [[0] * N for _ in range(N)]
    dr = [0, 1, 0, -1]          # 오른쪽, 아래, 왼쪽, 위
    dc = [1, 0, -1, 0]
    r = c = k = 0

    for num in range(1, N * N + 1):
        board[r][c] = num
        nr, nc = r + dr[k], c + dc[k]
        if not (0 <= nr < N and 0 <= nc < N) or board[nr][nc]:
            k = (k + 1) % 4
            nr, nc = r + dr[k], c + dc[k]
        r, c = nr, nc

    print(f"#{test_case}")
    for row in board:
        print(*row)
```
- 딕셔너리 대신 **방향 리스트 두 개** → 키가 0~3 연속 숫자면 리스트가 더 자연스러움
- `board[nr][nc] != 0` → `board[nr][nc]` (0은 거짓, 나머지는 참)
- `r, c` (row, column) 이름 → x, y보다 행/열 헷갈림이 적음

## 틀렸던 부분 한눈에 보기

| 실수 | 왜 틀렸나 | 바른 방법 |
|---|---|---|
| 이중 for문으로 위치 결정 | 줄 단위로만 방문 | 위치 변수를 들고 다니며 이동 |
| `(1, 0)`을 오른쪽으로 | `board[x][y]`에서 x는 **행** | 오른쪽 = `(0, 1)` |
| 오른쪽 다음 위 | 시계 방향은 오른쪽 → 아래 → 왼쪽 → 위 | 순서대로 배치 |
| `k = 0`이 반복문 안 | 매 칸마다 방향 리셋 | 케이스 시작에 한 번만 |
| `k += 1` / `k % (N + 1)` / `k % 3` | 3 다음 0으로 못 돌아감, 직접 공식 | `k = (k + 1) % 4` |
| 비어 있을 때 방향 전환 | 조건 반대 | 이미 채워졌을 때 전환 |
| `nx > N` | 인덱스 N도 범위 밖 | `0 <= nx < N` |
| board를 범위보다 먼저 확인 | 범위 밖 접근 에러 | 범위 검사를 `or` 앞에 |
| `f"# {test_case}"` | `#` 뒤 공백 | `f"#{test_case}"` |
| 0부터 채움 | 1부터 시작 | `range(1, N ** 2 + 1)` |

## 핵심 개념 정리

> [!IMPORTANT]
> **1. 시뮬레이션의 기본 틀: 상태를 들고 다니기**
> ```text
> 상태 = 위치 (x, y) + 방향 k
> 매 단계:
>     현재 위치에서 할 일 하기
>     다음 위치 계산
>     막혔으면 방향 바꾸고 다시 계산
>     이동
> ```
> for문은 **"몇 번 반복할지"**만 정하고, **위치는 변수**가 정함

> [!IMPORTANT]
> **2. 순환 = 나머지 연산 `%` (세 번째 등장 ⚠️)**
> `k = (k + 1) % 4` → 0, 1, 2, 3, 0, 1, …
> - [[Lv 0. 공 던지기]]: `(idx + 2) % n`
> - [[Lv 1. 모의고사]]: `pattern[i % len(pattern)]`
> - 달팽이 숫자: `(k + 1) % 4`
> **"돌아온다 / 반복된다 / 순환한다" → 바로 `%`**

> [!IMPORTANT]
> **3. 방향 리스트는 도는 순서대로**
> 방향을 "다음 것"으로 바꾸려면 리스트 순서 = 회전 순서
> 시계 방향: 오른쪽 `(0, 1)` → 아래 `(1, 0)` → 왼쪽 `(0, -1)` → 위 `(-1, 0)`

> [!IMPORTANT]
> **4. 0으로 채운 판 = 방문 체크**
> 0이면 아직 안 간 칸, 0이 아니면 이미 간 칸
> → 따로 방문 배열을 만들지 않아도 됨 (BFS의 `dist` 판과 같은 발상)

> [!IMPORTANT]
> **5. `board[x][y]`에서 x는 행(위아래)**
> 수학 좌표 (x = 가로)와 반대 → 헷갈리면 `r, c`로 이름 짓기

## 회고
- 1차 분석(규칙 파악)은 처음부터 정확했음 → 막힌 건 **구조**(이중 for문)와 **도구**(`%`)
- 위치를 변수로 들고 다니는 구조로 바꾼 뒤에는 피드백마다 빠르게 수정
- `%`는 모의고사에 이어 또 직접 공식을 만들다 막힘 → **패턴을 이름으로 기억하기: "순환 = %"**
- 이 틀(상태 + 다음 위치 + 방향 전환)은 싸피 시뮬레이션의 기본형 → 다음 시뮬레이션 문제에서 바로 써먹기
