# [이코테] 실전 문제. 왕실의 나이트

> [!NOTE]
> 문제 원문과 입출력 예시는 도서 저작물이라 이 노트에 옮기지 않았습니다.
> 문제는 책 **Chapter 4 구현, 실전 문제 "왕실의 나이트"**에서 확인하세요.

## 문제 핵심 (내 말로 한 줄)
- 8×8 체스판에서 `a1` 같은 위치에 있는 나이트가 **판 밖으로 나가지 않고** 이동할 수 있는 경우의 수 세기

## 유형
- 구현 / 시뮬레이션
- **8방향 이동** + 범위 검사 → [[예제 4-1. 상하좌우]]의 확장판
- 문자(열) → 숫자 좌표 변환

---

## 내 코드 (해설 보기 전, 한 번에 통과)
```python
n = str(input())
w_to_n = {"a": 1, "b": 2, "c": 3, "d": 4, "e": 5, "f": 6, "g": 7, "h": 8}
x, y = w_to_n.get(n[0]), int(n[1])          # x = 열(알파벳), y = 행(숫자)
move = [(-2, -1), (-2, 1), (2, -1), (2, 1), (-1, -2), (1, -2), (-1, 2), (1, 2)]
count = 0
for i in range(len(move)):
    nx, ny = x + move[i][0], y + move[i][1]  # 다음 위치 계산
    if 1 <= nx <= 8 and 1 <= ny <= 8:        # 판 안이면
        count += 1

print(count)
```

> [!TIP]
> 잘한 점
> - **힌트 없이, 해설도 안 보고 한 번에** 풀이
> - 나이트의 8가지 이동을 **빠짐없이** 정리
> - 체스판 좌표가 **1 ~ 8**이라는 점을 반영한 범위 검사
> - 알파벳 열 → 숫자 변환을 **딕셔너리**로 직관적으로 해결
> - 상하좌우의 "다음 위치 계산 → 범위 검사" 패턴을 8방향으로 확장

## 책 해설 코드
> 출처: 나동빈, 『이것이 취업을 위한 코딩 테스트다 with 파이썬』, Chapter 4 실전 문제
> 저자 GitHub: `ndb796/python-for-coding-test`

```python
# 현재 나이트의 위치 입력받기
input_data = input()
row = int(input_data[1])
column = int(ord(input_data[0])) - int(ord('a')) + 1

# 나이트가 이동할 수 있는 8가지 방향 정의
steps = [(-2, -1), (-1, -2), (1, -2), (2, -1), (2, 1), (1, 2), (-1, 2), (-2, 1)]

# 8가지 방향에 대하여 각 위치로 이동이 가능한지 확인
result = 0
for step in steps:
    # 이동하고자 하는 위치 확인
    next_row = row + step[0]
    next_column = column + step[1]
    # 해당 위치로 이동이 가능하다면 카운트 증가
    if next_row >= 1 and next_row <= 8 and next_column >= 1 and next_column <= 8:
        result += 1

print(result)
```

## 내 코드 vs 해설 비교

| 항목 | 내 코드 | 해설 |
|---|---|---|
| 열 변환 | 딕셔너리 `{"a": 1, ...}` | `ord(문자) - ord('a') + 1` |
| 좌표 순서 | (열, 행) = (x, y) | (행, 열) = (row, column) |
| 방향 순회 | `for i in range(len(move))` | `for step in steps` |
| 범위 검사 | `1 <= nx <= 8` (비교 연결) | `>= 1 and <= 8` (따로 비교) |
| 결과 | 동일 ✅ | 동일 ✅ |

> [!WARNING]
> **좌표 순서가 달라도 결과가 같은 이유**
> 나이트의 8방향은 (a, b)가 있으면 (b, a)도 있는 **대칭 집합** → 행과 열을 바꿔 적용해도 같은 결과
> 하지만 방향이 **비대칭**인 문제(예: 위로만 가는 말)에서는 행·열을 바꿔 쓰면 **틀림**
> → **`r, c`(행, 열)로 이름 짓고 순서를 통일**하는 습관 ([[D2. 1954 달팽이 숫자]] 참고)

## 다듬은 버전 (참고)
```python
pos = input()
r = int(pos[1])                        # 행 (숫자)
c = ord(pos[0]) - ord('a') + 1         # 열 (알파벳 → 1 ~ 8)

moves = [(-2, -1), (-2, 1), (2, -1), (2, 1),
         (-1, -2), (1, -2), (-1, 2), (1, 2)]

count = 0
for dr, dc in moves:                   # 방향을 바로 꺼내기
    nr, nc = r + dr, c + dc
    if 1 <= nr <= 8 and 1 <= nc <= 8:
        count += 1

print(count)
```
- `input()`은 이미 문자열 → `str()` 불필요
- `for dr, dc in moves` → 인덱스 없이 방향을 바로 언패킹
- 변수 이름 `r, c`로 행·열 순서를 명확하게

### 복잡도
- 시간: **O(1)** (항상 8방향만 확인), 공간: **O(1)**

## 핵심 개념 정리

> [!IMPORTANT]
> **1. `ord()`로 알파벳 → 숫자**
> ```python
> ord('a')                    # 97
> ord('c') - ord('a') + 1     # 3
> chr(97)                     # 'a'  (반대 방향)
> ```
> 알파벳은 번호가 1씩 연속 → **기준 문자와의 차이**로 순서를 구함
> 범위가 작으면 딕셔너리, 크면(a ~ z) `ord()`가 편함

> [!IMPORTANT]
> **2. 이동 방향이 특이해도 패턴은 같다**
> 상하좌우 4방향 → 대각선 8방향 → 나이트 8방향
> 방향 리스트만 바뀌고 **"다음 위치 계산 → 범위 검사"** 뼈대는 그대로

> [!IMPORTANT]
> **3. 행·열 순서 통일**
> 입력이 `a1`처럼 **열이 먼저** 와도, 코드 안에서는 **(행, 열)** 순서로 통일하면 헷갈리지 않음
