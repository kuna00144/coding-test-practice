# 키패드 누르기 (프로그래머스 Lv.1)

## 문제 요약
- 휴대폰 키패드(1~9, `*`, 0, `#`)를 왼손·오른손 엄지로 누름
- 왼손은 `*`, 오른손은 `#`에서 시작
- 규칙
  - 왼쪽 줄 `1, 4, 7` → 왼손
  - 오른쪽 줄 `3, 6, 9` → 오른손
  - 가운데 줄 `2, 5, 8, 0` → **더 가까운 손** (상하좌우 이동 칸 수 기준)
  - 거리가 같으면 → `hand`(오른손잡이/왼손잡이)에 따라
- 각 번호를 누른 손을 `"L"`, `"R"`로 이어붙인 **문자열** 반환

> [!info] 유형
> 구현 / **값(키 번호) → 좌표 변환** / 맨해튼 거리 / 조건 분기
> 격자 위 위치 계산 → 싸피 시뮬레이션·BFS 감각의 기초

---

## 1차 분석
- 전체 위치 계산을 할 수 있는 무언가가 있어야 할 것 같음 → **키패드 좌표 딕셔너리**
- 이건 밖으로 나가는 문제가 아니라 **범위 검사가 필요 없는** 문제

> [!success] 잘한 점
> - **설계를 처음부터 혼자** 완성 (왼쪽 줄 / 오른쪽 줄 / 가운데 줄 + 동점 처리)
> - 키패드 → 좌표 딕셔너리를 스스로 떠올림 ([[Lv 0. 캐릭터의_좌표]]에서 배운 딕셔너리 활용)
> - 시작 위치를 `*`, `#` 좌표로 정확히 설정
> - "범위 검사가 필요 없다"는 걸 문제 성격으로 판단함

## 풀이 과정

### 1차 ❌ 설계 완성, 문법 도구에서 걸림
```python
direct = {"1": (0, 0), "2": (0, 1), ...}       # 키가 문자열
...
if numbers[i] == 2 or numbers[i] == 4 or numbers[i] == 6 or numbers[i] == 8:
    if direct.get(numbers[i]) - l_now < direct.get(numbers[i]) - r_now:
```
- numbers에는 숫자 `1`이 들어오는데 딕셔너리 키는 문자열 `"1"` → `direct.get(1)`은 `None`
- 가운데 줄을 `2, 4, 6, 8`로 잘못 적음 → 정답은 `2, 5, 8, 0`
  - 게다가 4, 6은 왼쪽/오른쪽 if에도 걸려서 **두 번 추가**됨
- 튜플끼리 빼기 `(1, 1) - (0, 0)` → 에러 ([[Lv 1. 공원 산책]]의 튜플 연산 함정 재발)
- 반환 형태를 리스트로 둠 (정답은 문자열)

### 2차 ❌ 키·가운데 줄·`in` 수정, 거리 공식과 좌표 꺼내기에서 걸림
```python
now_i = direct.get(numbers[i])
nx, ny = direct.get(numbers[i][0]), direct.get(numbers[i][1])   # ❌
l_direct = abs(nx) + abs(l_now[0]) + abs(ny) + abs(l_now[1])    # ❌
```
- `numbers[i][0]` → `numbers[i]`는 **숫자 하나**라 인덱싱 불가
  - 좌표는 이미 `now_i`에 들어 있음 → **값(키 번호) vs 좌표** 혼동 재발 ⚠️
- 거리 공식이 "각각 양수로 만들어서 **전부 더하기**"
  - 왼손 4번 `(1, 0)` → 5번 `(1, 1)`: 실제 거리 1, 이 공식으론 3
  - 거리는 **차이**의 절댓값을 더해야 함
- 반환 형태는 여전히 리스트

### 3차 → 성공 🎉
- 좌표는 `now_i[0]`, `now_i[1]`에서 꺼냄
- 거리: `abs(행 차이) + abs(열 차이)`
- answer를 문자열 `""`로 두고 `+=`로 이어붙임

## 최종 코드 (통과)
```python
def solution(numbers, hand):
    n = len(numbers)
    answer = ""
    direct = {1: (0, 0), 2: (0, 1), 3: (0, 2), 4: (1, 0), 5: (1, 1), 6: (1, 2),
              7: (2, 0), 8: (2, 1), 9: (2, 2), "*": (3, 0), 0: (3, 1), "#": (3, 2)}
    ls, rs = direct.get("*"), direct.get("#")
    l_now, r_now = ls, rs                          # 시작 위치

    for i in range(n):
        now_i = direct.get(numbers[i])             # 누를 키의 좌표
        l_direct = abs(now_i[0] - l_now[0]) + abs(now_i[1] - l_now[1])
        r_direct = abs(now_i[0] - r_now[0]) + abs(now_i[1] - r_now[1])

        if numbers[i] in (1, 4, 7):                # 왼쪽 줄
            answer += "L"
            l_now = now_i

        if numbers[i] in (3, 6, 9):                # 오른쪽 줄
            answer += "R"
            r_now = now_i

        if numbers[i] in (2, 5, 8, 0):             # 가운데 줄
            if l_direct < r_direct:
                answer += "L"
                l_now = now_i
            elif l_direct == r_direct:             # 거리가 같으면 손잡이
                if hand == "right":
                    answer += "R"
                    r_now = now_i
                else:
                    answer += "L"
                    l_now = now_i
            else:
                answer += "R"
                r_now = now_i

    return answer
```

### 다듬은 버전 (참고)
```python
def solution(numbers, hand):
    pos = {1: (0, 0), 2: (0, 1), 3: (0, 2),
           4: (1, 0), 5: (1, 1), 6: (1, 2),
           7: (2, 0), 8: (2, 1), 9: (2, 2),
           "*": (3, 0), 0: (3, 1), "#": (3, 2)}

    def dist(a, b):                                # 맨해튼 거리
        return abs(a[0] - b[0]) + abs(a[1] - b[1])

    left, right = pos["*"], pos["#"]
    main = "L" if hand == "left" else "R"          # 동점일 때 쓸 손
    answer = []

    for num in numbers:
        target = pos[num]
        if num in (1, 4, 7):
            use = "L"
        elif num in (3, 6, 9):
            use = "R"
        else:
            dl, dr = dist(left, target), dist(right, target)
            if dl < dr:
                use = "L"
            elif dl > dr:
                use = "R"
            else:
                use = main

        if use == "L":                             # 손 위치 갱신은 한 곳에서만
            left = target
        else:
            right = target
        answer.append(use)

    return "".join(answer)
```
바뀐 점:
- `for num in numbers` → 인덱스 i 없이 번호를 바로 꺼냄
- 거리 계산을 **함수 `dist`로 분리** → 같은 식을 두 번 쓰지 않음
- "어느 손인지 정하기"와 "손 위치 갱신하기"를 **분리** → `l_now = now_i` 같은 줄이 6번 → 2번
- `if / elif / else`로 세 경우가 **하나만** 실행된다는 게 코드에서 보임
- 동점 손을 `main`으로 미리 정해서 중첩 if 제거
- `pos["*"]`처럼 대괄호로 꺼내기 (키가 확실히 있을 때는 `.get()` 대신 `[]`가 일반적)

### 복잡도
- 시간: **O(N)** (N = numbers 길이, 번호마다 상수 시간)
- 공간: **O(N)** (결과 문자열)

## 틀렸던 부분 한눈에 보기

| 실수 | 왜 틀렸나 | 바른 방법 |
|---|---|---|
| 딕셔너리 키를 `"1"` (문자열)로 | numbers엔 숫자 `1`이 들어옴 → `1 != "1"` | 키 자료형을 입력에 맞추기 |
| 가운데 줄을 `2, 4, 6, 8`로 | 좌표 그림과 대조 안 함 | 열 번호 1인 키: `2, 5, 8, 0` |
| 4, 6이 두 if에 동시에 걸림 | 독립된 if 여러 개 | 겹치지 않게 + `if/elif/else` |
| 튜플 빼기 `(1, 1) - (0, 0)` | 튜플은 원소별 연산 안 됨 | 값을 하나씩 꺼내서 계산 |
| `numbers[i][0]` | 숫자 하나는 인덱싱 불가 / **값 vs 좌표** 혼동 | 좌표 변수 `now_i[0]` |
| `abs(a) + abs(b) + ...` | 각각 양수로 만들어 전부 더함 | **차이**의 절댓값: `abs(a - b)` |
| 반환을 리스트로 | 입출력 예시의 형태 확인 안 함 | 문자열 `+=` 또는 `"".join()` |
| `import math` | `abs()`는 기본 함수 | import 불필요 |

## 핵심 개념 정리

> [!important] 1. 값 → 좌표 변환 = 딕셔너리
> 키 번호(값)를 위치(좌표)로 바꾸는 표를 만들어두면 거리 계산이 쉬워짐
> ```python
> pos = {1: (0, 0), 2: (0, 1), ...}
> target = pos[5]     # (1, 1)
> ```
> 번호와 좌표는 **다른 것** → `numbers[i]`는 번호, `pos[numbers[i]]`가 좌표 ⚠️ (값 vs 좌표 4번째 등장)

> [!important] 2. 맨해튼 거리 (상하좌우로만 움직일 때의 거리)
> ```python
> abs(r1 - r2) + abs(c1 - c2)
> ```
> - 행이 몇 칸 차이 + 열이 몇 칸 차이
> - BFS 최단거리, 격자 문제에 계속 나옴

> [!important] 3. 딕셔너리 키 자료형
> - `1`(int)과 `"1"`(str)은 **다른 키**
> - 입력이 어떤 자료형인지 예시에서 먼저 확인

> [!important] 4. 문자열 만들기 두 가지
> ```python
> answer = ""
> answer += "L"              # 이어붙이기
> ```
> ```python
> answer = []
> answer.append("L")
> return "".join(answer)     # 리스트 → 문자열
> ```
> 길이가 아주 길면 `join` 방식이 더 효율적 (지금 문제 크기에선 둘 다 OK)

> [!important] 5. "결정"과 "실행" 분리
> 어느 손을 쓸지 먼저 **정하고**(`use`), 손 위치 갱신은 **한 번만** → 중복 코드 감소, 실수 감소

> [!important] 6. 반복되는 계산은 함수로
> 같은 거리 공식을 두 번 쓰면 → `def dist(a, b):`로 분리
