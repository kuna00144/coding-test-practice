# 크레인 인형뽑기 게임 (프로그래머스 Lv.1)

## 문제 핵심 (내 말로)
- 격자의 각 열에서 **맨 위 인형**을 크레인으로 집어 바구니에 쌓기
- 바구니에 **같은 인형 두 개가 맞닿으면** 터져서 사라짐
- 터진 인형의 총 개수 반환

## 유형
- 구현 / 시뮬레이션
- 격자를 **열 단위로** 읽기
- **스택** (맨 위에만 넣고, 맨 위에서만 빼기)

---

## 풀이 과정

### 1차 ❌ 다 모은 뒤 한꺼번에 지우기
```python
def solution(board, moves):
    kit = []
    count = 0
    for move in moves:
        for i in range(len(board)):
            if board[i][move - 1] != 0:          # ✅ 위에서부터 첫 인형 찾기
                kit.append(board[i][move - 1])
                board[i][move - 1] = 0           # ✅ 집은 칸 비우기
                break                            # ✅ 한 열에서 하나만

    for j in kit:                                # ❌
        if kit[j] == kit[j + 1]:
            del kit[j:j+2]
            count += 2
    return count
```

> [!TIP]
> 잘한 점
> - 열 번호를 `move - 1`로 변환 (번호 1부터 vs 인덱스 0부터)
> - 위에서부터 내려가며 **첫 인형**을 찾고 `break`
> - 집은 칸을 `0`으로 비우기
> - 스스로 찾은 문제점: `for j in kit`는 인덱스가 아니라 **값**을 꺼냄, `j + 1` 범위 초과, 지우면서 **길이가 줄어듦**

**더 근본적인 문제: 연쇄 폭발을 못 셈**
```text
바구니에 들어간 순서: 1, 2, 2, 1
```
- 한꺼번에 훑으면 가운데 `2, 2`만 지워지고 `[1, 1]`이 남음
- 실제 게임에선 `2, 2`가 터진 순간 `1`과 `1`이 맞닿아서 **이것도 터짐** → 정답 4개, 이 방식은 2개

> [!IMPORTANT]
> **"다 모은 다음 한꺼번에"가 아니라 "넣는 순간에" 확인**
> 넣으려는 인형을 바구니의 **맨 위 인형 하나**와만 비교하면 됨
> → `del`, 범위 계산, 길이 변화 문제가 전부 사라짐

### 2차 ❌ 스택 도입, 터질 때 보드를 안 비움
```python
if len(kit) != 0 and kit[-1] == board[i][move - 1]:
    kit.pop()
    count += 2
    break                                       # ❌ 보드 칸을 안 비우고 탈출
kit.append(board[i][move - 1])
board[i][move - 1] = 0
break
```
- 터지는 경우 `board[i][move - 1] = 0`이 실행되지 않음
- 인형이 **보드에 그대로 남아서**, 같은 열을 또 집으면 같은 인형을 다시 집게 됨

> [!IMPORTANT]
> 인형을 **보드에서 빼는 일**은 터지든 안 터지든 **항상** 일어남
> → 공통 동작 ([[D2. 1940 가랏! RC카!]] "공통 동작은 분기 밖으로")

## 최종 코드 (통과)
```python
def solution(board, moves):
    kit = []                                     # 바구니 (스택)
    count = 0
    for move in moves:
        for i in range(len(board)):              # 위에서부터 내려가며
            if board[i][move - 1] != 0:          # 첫 인형 발견
                if len(kit) != 0 and kit[-1] == board[i][move - 1]:   # 맨 위와 같으면
                    kit.pop()                    # 터짐
                    board[i][move - 1] = 0
                    count += 2
                    break
                kit.append(board[i][move - 1])   # 다르면 쌓기
                board[i][move - 1] = 0
                break
    return count
```

### 복잡도
- 시간: **O(M × N)** (M = 크레인 이동 횟수, N = 격자 크기, 열마다 위에서부터 탐색)
- 공간: **O(M)** (바구니)

## 다듬은 버전 (참고)
```python
def solution(board, moves):
    basket = []
    count = 0
    for move in moves:
        col = move - 1
        for row in range(len(board)):
            doll = board[row][col]
            if doll:                             # 0이 아니면 인형
                board[row][col] = 0              # 공통 동작: 항상 보드에서 빼기
                if basket and basket[-1] == doll:   # 비어 있지 않고 맨 위와 같으면
                    basket.pop()
                    count += 2
                else:
                    basket.append(doll)
                break
    return count
```
바뀐 점:
- `board[row][col] = 0`을 **분기 앞으로** → 두 곳에 쓰던 줄이 한 곳으로, 빠뜨릴 일이 없음
- `doll = board[row][col]`로 한 번 꺼내서 재사용 → 긴 인덱스 반복 제거
- `len(kit) != 0` → `basket` (빈 리스트는 거짓, 값이 있으면 참)
- `if doll:` → 0은 거짓, 나머지는 참 ([[D2. 1954 달팽이 숫자]] 다듬은 버전과 같은 문법)
- 변수 이름 `kit` → `basket`, `i` → `row`, `move - 1` → `col`

## 틀렸던 부분 한눈에 보기

| 실수 | 왜 틀렸나 | 바른 방법 |
|---|---|---|
| `for j in kit` + `kit[j]` | j는 인덱스가 아니라 **값** (값 vs 좌표 ⚠️) | 애초에 스택으로 해결 |
| 다 모은 뒤 한꺼번에 삭제 | 연쇄 폭발(1,2,2,1)을 못 셈 | 넣는 순간 맨 위와 비교 |
| 반복 중 `del`로 리스트 변경 | 길이가 줄어 인덱스가 어긋남 | 스택은 맨 위만 다룸 |
| 터질 때 보드 칸을 안 비움 | 같은 인형을 또 집게 됨 | 보드에서 빼기는 **공통 동작** |

## 핵심 개념 정리

> [!IMPORTANT]
> **1. 스택 (Stack)**
> 맨 위에만 넣고, 맨 위에서만 빼는 구조
> ```python
> stack = []
> stack.append(x)     # 맨 위에 넣기
> stack[-1]           # 맨 위 보기 (비어 있으면 에러!)
> stack.pop()         # 맨 위 꺼내서 지우기
> ```
> **"방금 넣은 것과 비교"**, **"짝이 맞으면 없앰"** → 스택 신호
> (괄호 검사, 같은 숫자 연속 제거 등)

> [!IMPORTANT]
> **2. 빈 스택 체크 먼저**
> `if basket and basket[-1] == doll:`
> `and`는 앞이 거짓이면 뒤를 안 봄 → 비었을 때 `basket[-1]` 에러 방지
> ([[Lv 1. 공원 산책]]의 "범위 검사 먼저"와 같은 단락 평가)

> [!IMPORTANT]
> **3. 상황이 바뀌는 즉시 처리하기**
> 결과가 **앞의 처리에 따라 연쇄적으로** 달라지면 → 나중에 한꺼번에 X, **그때그때** O

> [!IMPORTANT]
> **4. 반복 중에 리스트를 지우지 않기**
> `for`로 도는 리스트를 `del`로 줄이면 인덱스가 어긋남
> → 새 리스트에 담거나, 스택처럼 끝에서만 다루기

> [!IMPORTANT]
> **5. 격자를 열 단위로 읽기**
> `for row in range(N): board[row][col]` → col은 고정, row만 내려감
> 위에서부터 처음 만나는 값 = 그 열의 맨 위

## 공부해야 할 부분
- [ ] 스택 패턴 (`append`, `[-1]`, `pop`) 손에 익히기
- [ ] **공통 동작은 분기 밖으로** — RC카에 이어 두 번째
- [ ] 반복 중에 리스트 수정하지 않기
- [ ] `for x in 리스트`는 **값**, 인덱스가 필요하면 `range(len(...))`

## 회고
- 격자를 열 단위로 읽는 부분은 **혼자 완벽하게** 해결
- 첫 시도의 문제점(인덱스, 범위, 길이 변화)을 **스스로 진단**함
- 막힌 건 "언제 확인하느냐"라는 설계 → 스택이라는 도구로 해결
- 마지막 버그는 RC카와 같은 **"공통 동작 빠뜨리기"** → 다음엔 분기 전에 공통 동작부터 쓰기
